# 脚本卖点整理

商品脚本生成会先根据商品名称、描述、用法优势、价格和图片分析整理卖点，再生成分镜。首次生成和重新生成各增加一次文本模型调用；整个过程仍使用一次“生成脚本”操作，进度中会显示“整理全部商品卖点”。普通主题视频不经过这一步。

脚本页的小白模式、导演模式均展示完整清单：产品特点、用户收益、主卖点、资料依据、建议画面和计划关联镜头。没有用于当前方案的卖点显示“本方案未安排”，不会因短视频时长限制只保留前三条。切换方案会更新镜头关联。每次整理的完整性仍取决于输入资料与模型输出。

来源分为“用户资料提供”“图片识别 · 请核对”“待确认推断”。服务端会核对引用片段是否出现在对应资料中；这只说明来源，不代表产品主张已经得到独立验证。无依据的信息不会作为已确认卖点关联到分镜。修改台词或画面后，需要重新核对生成时的镜头关联。

卖点以 `scripts.selling_point_plan` JSON 保存，每个分镜的 `sellingPointIds` 指向清单中的 ID。不同脚本保存各自生成时的资料快照，读取或刷新不会再次调用模型。迁移 `0020_script_selling_points` 会在下次数据库初始化时自动添加可空字段；旧脚本保持可用，重新生成后才有卖点整理。

卖点解析失败会按现有 JSON 修复机制重试一次；仍失败则返回错误，不静默生成缺少卖点的结果。脚本替换与项目状态更新在同一事务内，保存失败会保留原来的脚本。

本实现将产品定位、特性到用户收益的转译、证据与画面关联组织为应用内提示词，不依赖运行时安装外部 skill 或额外服务。
